# AirGrid — India Open-Data Air-Quality Dashboard (PWA)

AirGrid is an installable, offline-capable dashboard over CPCB-shaped air-quality data for
**Chennai, Delhi, Bengaluru, Mumbai and Hyderabad**. It computes AQI itself from the published
Indian CPCB breakpoints, renders it with hand-rolled SVG (no chart library), works with no
network after the first visit, and enforces a hard performance budget in CI.

Next.js was not used on purpose. This project is about shipping a small, fast, accessible client:
the whole app is ~59 kB of gzipped JavaScript *including* React, and every byte is checked by
`npm run check:budget`.

## Run it

```bash
npm install
npm run dev          # http://localhost:5300
npm test             # 48 tests (3 unit files + 1 jsdom render file)
npm run build        # production bundle in dist/
npm run check:budget # fails the build if the bundle grows past budget
npm run data         # regenerate src/data/air-quality.json (byte-identical)
```

Docker (nginx, non-root, gzip, long-lived asset caching):

```bash
docker build -t airgrid .
docker run --rm -p 8080:8080 airgrid   # http://localhost:8080
```

## What it actually does

**AQI is computed, not copied.** `src/lib/aqi.js` implements the CPCB sub-index tables for
PM2.5, PM10 and NO₂ and takes the **worst** sub-index as the AQI, naming the pollutant that
produced it. Indian breakpoints differ from the US EPA ones (PM2.5 = 60 µg/m³ is *Satisfactory*
in India, *Moderate* in the US), and mixing them is the classic bug in Indian AQI dashboards —
so they are unit-tested at every band edge.

**Two data modes, one shape.** Default mode reads the committed snapshot: 5 cities × 45 days ×
25 stations, generated by `scripts/generate-data.mjs` from a seeded `mulberry32` PRNG, so the
file is reproducible byte-for-byte. Live mode (`VITE_DATA_MODE=live` + a free
`VITE_DATA_GOV_KEY`) queries the data.gov.in CPCB resource, folds its one-row-per-pollutant
records into stations, and replaces today's city reading with the mean of its live stations.
If the key is missing, the request 429s, or the network is down, `loadDashboard()` **never
throws** — you get the snapshot plus a visible warning banner. There is a test for each of
those failure paths.

**Offline is real.** `public/sw.js` is ~1 kB of hand-written cache logic, no Workbox: the app
shell is cache-first on install, API/JSON responses are stale-while-revalidate, and navigation
requests fall back to the cached shell. An offline badge flips when `navigator.onLine` changes.

**Accessibility is tested, not claimed.** Skip link, semantic landmarks, `aria-pressed` on every
toggle, `role="status"` on the sync badge, a screen-reader sentence describing the current air
quality, chart text alternatives, and the full chart rendered as a real `<table>` inside a
`<details>` element. Focus-visible outlines, ~4.5:1 contrast on body text, and
`prefers-reduced-motion` disables all animation.

## API / data contract

The dashboard talks to exactly one function:

```js
const payload = await loadDashboard(); // { cities, stations, mode, warning, generatedAt, source }
```

- `mode`: `bundled` | `live` | `fallback`
- `warning`: `null` or a human sentence shown in the banner
- `city.days[]`: `{ date, pm25, pm10, no2, temp_c, humidity, aqi, live? }`
- `stations[]`: `{ id, name, cityId, zone, aqi, pm25, dominant, indices, lastUpdated }`

`validateSnapshot()` is exported from `src/lib/analytics.js` and asserted in the test suite
against the committed JSON, so a corrupted snapshot fails CI instead of rendering nonsense.

## Data attribution

In bundled mode the readings are a **synthetic reference series shaped like CPCB data** — useful
for demos, tests and offline work, and explicitly labelled `source: "synthetic-snapshot"` in
`air-quality.json`. In live mode the data comes from
[data.gov.in](https://data.gov.in) under the Government Open Data Licence — India. This is not a
regulatory monitoring product; do not make health decisions from a demo build.

## Known limitations

- Live mode has no server-side key: `VITE_*` values are baked into the bundle and therefore
  public. A production deployment should proxy data.gov.in through a small backend that holds
  the key (see `project-06-billbook-gst-saas/` for the FastAPI pattern).
- Live mode only refreshes the latest day; the 45-day history stays the bundled series and the
  banner says so.
- No screenshot-based visual regression tests (no headless Chrome in the build environment).
